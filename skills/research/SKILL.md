# research — 研究/分析任务的标准编排

当任务是「调研 / 研究 / 分析 / 总结 / 根据某些资料（目录、文档、PDF、PPT、Excel）产出（报告、网站、文档、方案）」时，**严格按以下步骤**，不得跳过。

> **前提：你拥有完整文件访问权（bypassPermissions）。任何本地文件都能读。严禁声称「权限问题」「无法访问」。**

## 步骤（MANDATORY）

1. **定位资料**：确认要研究的目录/文件（用 `Glob`/`ls` 列出）。

2. **★ 强制提取（第一步必做）**：对资料目录运行 doc-extract，把所有二进制文档（PDF/PPTX/Word/Excel/图片）转成文本，汇总成 SOURCE.md：
   ```bash
   python .claude/skills/doc-extract/extract.py --batch "<资料目录>" --out "<资料目录>/SOURCE.md"
   ```
   （相对路径 + 正斜杠;单个文件用不带 `--batch` 的形式。详见 doc-extract skill。）

3. **通读真实资料**：`Read` 该 `SOURCE.md`（以及目录里的 .md/.txt 源）。这是你的**唯一事实来源**。

4. **综合产出**：仅以提取到的真实内容为依据产出。引用应能追溯到 SOURCE.md 里的具体表述（专有名词、数字、结构应来自资料，而非泛泛而谈）。

5. **缺失处理**：若某文件提取失败（如图片需 OCR 未装），显式说明并继续其余文件，**不得整体放弃，更不得用「权限问题」搪塞**。

## 铁律(硬性)
- **doc-extract --batch 必须是第一个工具调用**，即使目录里已有 .md/.txt/README 也**必须先跑**，不得因"已有文本"而跳过。
- **门禁**：`SOURCE.md` 实际生成前，禁止 Read 单个文档、禁止开始写产出。
- **分步产出**：先 Write 骨架，再多次小 Edit 补内容；文件写完前不结束回合。
- **自检汇报(必填)**：产出后附「核对清单」——SOURCE.md 字符数/文档数 + 3–5 条来自真实资料的具体事实(注明出处文件名)，供人工抽检。

## 禁止
- ❌ 不读资料、仅凭一般知识硬编。
- ❌ 声称「读不了 / 没权限 / 无法访问」（你有完整权限，二进制用 doc-extract 即可读）。
- ❌ 跳过 doc-extract（即使有文本也必须先跑 --batch）。
- ❌ 在没有 SOURCE.md / 没 Read 真实资料的情况下就开始写最终产物。
- ❌ 省略核对清单。
